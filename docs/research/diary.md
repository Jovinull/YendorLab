# Scientific diary

## 2026-10-30 — M4 exploration pilot

We sought a measurable learned skill before attempting full Brogue. Chose new-cell exploration because it has direct objective feedback and cheap bounded episodes; stair navigation and survival need longer or more confounded horizons. The old tabular state omitted route and visit history. A 16-weight action-value model trained on real Brogue for two 30-episode runs. Both improved discovered-cell counts against their zero-weight initial policy on 16 held-out seeds, but neither approached the manual heuristic. A post-hoc fixed-north control showed that much of the policy is a directional preference; additional learned action changes reduced stalling on separate diagnostic seeds. The first final evaluation attempt for model A failed during reset and was rerun identically after diagnostic error handling was added. Gymnasium `check_env` passed for a movement-only wrapper after excluding nondeterministic RSS from `info`. ASan/UBSan passed a real death path. The strongest measured engineering bottleneck was repeated process startup from `/mnt/c`, not linear inference. Next: replicate with clean-revision source hashes, audit special perception and contextual actions, and design a more challenging navigation task.

## 2026-10-30 — M1–M3 bounded investigation

Goal: turn the M0 adapter into a real CPU learning pipeline. Expected canonical `notifyEvent` callbacks to classify outcomes, but found that death passes through a death acknowledgment, another acknowledgment and a recording prompt before the callback. Added context markers and automatic prompt handling; real seed 123 death then ended at 80 input events and turn 76. Quit ended at turn 0. A test-only build exercised victory and supervictory callbacks; no live victory was obtained. Inventory apply/confirmation was exercised with starting food. The seed catalog body matched on 6,773 lines after declared CRLF/header normalization, while upstream's original comparator still fails on the Windows checkout.

Expected the heuristic to provide a strong exploration baseline; observed only limited improvement in three short validation episodes and frequent no-progress truncation. Implemented tabular Q-learning to test the complete collect-update-checkpoint-evaluate flow without heavy CPU dependencies. Four real episodes produced 531 updates, but three-seed post-training reward was lower than the untrained Q baseline. After two more episodes the measured shaped reward increased, yet all evaluations had zero natural completions and the sample is too small to infer improvement. Decision: keep the pipeline for narrow exploration research; complete the game contract and evaluate on a frozen larger protocol before longer training. See [results](../results/m1-m3.md).

## 2026-10-30 — M0

Goal: determine whether official Brogue CE can be controlled headlessly without changing game rules. Expected an input hook might exist near the console abstraction. Found `nullConsole` but its input callback returned without an action; upstream `-vn` was playback only. BrogueBot showed a historical Lua integration, but its source replacement approach was too broad for this first revision. Built upstream with SDL and terminal disabled, then added a platform-only JSON/stdin patch. Two seeds advanced real game turns. Repeated seed/action policy produced identical restricted observations in the tested WSL build. Random runs were all truncated and stayed at depth 1, so there is no valid game outcome comparison. Next: context-aware actions, visible terrain, natural terminal tests and upstream regression validation.
